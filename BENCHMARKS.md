# BENCHMARKS

Generated by `scripts/benchmark.py` (5 runs per pipeline scenario). Raw numbers: `benchmarks/results.json`.

**Machine:** Intel(R) Xeon(R) Processor @ 2.10GHz, 2 cores, Python 3.13.18, no GPU.

## What is measured and what is not

| Component | Status |
|---|---|
| Silero VAD inference + end-of-speech delay | **Measured** (real model, this CPU) |
| Gateway, streaming-ASR logic, batching queue, TTS framing, publishers | **Measured** (real code, wall clock, real time) |
| Whisper / NLLB / Piper compute time | **NOT measured here** |
| GPU numbers, LiveKit network RTT | **Not measured** |

The sandbox could not download model weights (Hugging Face is unreachable), so the real models are benchmarked only when you run `python scripts/benchmark.py --real asr,nmt,tts` on a machine that has them. Nothing below pretends otherwise: rows labelled *simulated* use fixed sleeps that I chose, not measurements.

## 1. Voice activity detection (real)

| Metric (ms) | p50 | p95 | max |
|---|---|---|---|
| Silero ONNX per 32 ms window | 0.13 | 0.20 | 0.45 |
| Last spoken sample -> gate closes (`end` event) | 320 | 320 | 320 |

Real-time factor 0.00428. The end-of-speech delay is dominated by `VAD_MIN_SILENCE_MS=300`: the gate has to hear that much silence before it can close the utterance. It is added to every end-to-end figure that is measured from the last spoken sample.

## 2. Pipeline overhead with mock models (real orchestration, real time)

Three utterances of real speech (`tests/data/speech_en.wav`) are fed at 1x speed through `LiveKitGateway` (fake room) -> VAD -> ASR -> NMT -> TTS -> publishers, with listeners for Spanish and French.

| Metric (ms) | p50 | p95 | max |
|---|---|---|---|
| Last spoken sample -> final subtitle published | 356 | 360 | 360 |
| VAD gate closed -> final subtitle published | 22 | 23 | 23 |
|   of which ASR stage (final transcript ready) | 0.76 | 0.94 | 0.99 |
|   of which NMT stage | 21 | 22 | 22 |
|   of which publish | 0.07 | 0.19 | 0.39 |
| Last spoken sample -> first TTS frame published | 361 | 366 | 368 |

With instant models the 'ASR stage' is the time the streaming driver needs to run its final pass; the remaining wall-clock time is the VAD hang-over. This is the floor the real models add to.

## 3. Budget under assumed model costs (SIMULATED)

Same run, but every ASR pass sleeps 350 ms, every NMT batch 150 ms and TTS 120 ms before its first audio. These delays are **assumptions** chosen to look like a small model on a modern CPU/GPU; replace them with section 5 numbers when you have them.

| Metric (ms) | p50 | p95 | max |
|---|---|---|---|
| Last spoken sample -> final subtitle published | 852 | 857 | 857 |
|   ASR stage | 351 | 352 | 352 |
|   NMT stage | 172 | 173 | 174 |
| Last spoken sample -> first TTS frame published | 976 | 982 | 984 |

Budget (`shared/config.py`): end-to-end 2000 ms, ASR 1000 ms, NMT 500 ms, TTS 500 ms. `tests/e2e/test_meeting_flow.py` asserts < 2000 ms for both scenarios and checks that a 1.6 s ASR is reported as a violation.

## 4. NMT batching (real queue, mock model with a fixed cost model)

16 concurrent requests, model cost = 80 ms per batch + 10 ms per item: batched total **242 ms** (batches [16]) versus 1440 ms one at a time, a 5.94x speed-up. This shows the queue mechanics only; the cost model is an assumption.
